# Счета PDF в таблицу Excel

**Задача.** В бухгалтерию или к менеджеру приходит пачка счетов от разных
поставщиков. Каждый свёрстан по-своему. Чтобы свести их в одну таблицу,
человек открывает файл за файлом и перебивает цифры руками — долго и с опечатками
там, где они дороже всего.

**Что сделано.** Скрипт берёт папку с PDF, вытаскивает текст и отдаёт его языковой
модели, которая возвращает поля документа. На выходе Excel из двух листов:
сводка по счетам и детализация по позициям. Суммы лежат числами, поэтому итоги
считаются формулами сразу.

**Результат прогона:** 5 счетов за 22 секунды, файл
[`output/invoices.xlsx`](output/invoices.xlsx).

| Номер | Дата | Поставщик | НДС, % | Всего |
|---|---|---|---|---|
| 2026/114 | 19.07.2026 | ООО «Грузовые Линии» | 20 | 120 360 |
| INV-000892 | 03.07.2026 | ИП Кузнецова А. В. | 0 | 30 500 |
| СФ-7781 | 28.06.2026 | АО «ТехноСнаб» | 20 | 93 312 |

## Точность проверена, а не заявлена

Счета генерируются скриптом `make_samples.py` из заранее известных данных,
и та же программа сохраняет эталон `samples/expected.json`. После разбора
`check.py` сверяет каждое поле и каждую позицию с эталоном:

    совпало 81 из 81 значений (100.0%)

Это ровно тот вопрос, который заказчик задаёт первым: «а оно точно не переврёт
цифры». Ответ измеряется на его же документах перед началом работы.

## Как запустить

    python3 -m venv .venv && .venv/bin/pip install -r ../requirements.txt
    cp ../.env.example ../.env    # вписать ключ модели
    .venv/bin/python make_samples.py   # сгенерировать демо-счета
    .venv/bin/python extract.py        # разобрать в таблицу
    .venv/bin/python check.py          # измерить точность

## Решения, которые обычно всплывают на реальном заказе

- **Модель вместо регулярных выражений.** У каждого поставщика своя вёрстка:
  «Счёт на оплату № 417», «INV-000892», «СФ-7781». Шаблонный парсер ломается
  на втором же новом поставщике, модель читает документ как человек.
- **Температура ноль и строгий JSON.** Ответ модели разбирается программой,
  поэтому свободный текст недопустим; формат ответа задан жёстко.
- **Прямой запрет выдумывать.** В инструкции сказано: нет поля — ставь `null`.
  В деньгах правдоподобная выдумка хуже пустой ячейки.
- **Суммы числами.** Как и в кейсе с парсером: строка «120 360,00 руб.» в Excel
  бесполезна, по ней не построить ни сумму, ни сводную таблицу.

## Ограничения, о которых честно говорю заказчику

Сканы и фотографии документов этот скрипт не читает — здесь текстовый слой PDF.
Для сканов нужен OCR, это отдельная работа и другой срок. Документы для демо
выдуманы: чужие счета в публичный кейс класть нельзя.

Сделано как демонстрация подхода, реального клиента за этим кейсом нет.
